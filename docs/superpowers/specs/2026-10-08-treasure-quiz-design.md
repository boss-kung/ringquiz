# Treasure Quiz: สเปก MVP สำหรับเล่นกันสองคน

วันที่: 8 ตุลาคม 2026  
สถานะ: Revised design; รอผู้ใช้รีวิว
ชื่อใช้งานในสเปก: **Treasure Quiz**

## 1. เป้าหมาย

สร้างเว็บเกมส่วนตัวสำหรับคนสองคน:

- **Host:** ผู้ตั้งคำถาม จัดรางวัล และควบคุมเกม
- **Player:** แฟนของ Host ซึ่งเป็นผู้เข้าแข่งขันเพียงคนเดียว

Player เล่นเกมตอบคำถาม 8 รอบเพื่อสะสมทองและเพชร ก่อนใช้ทรัพยากรทั้งหมดเปิดหีบรางวัลหลายใบ หีบให้รางวัลเป็นเงินบาทตั้งแต่ระดับสตางค์ขึ้นไป เงินบาทถูกสะสมข้ามเกมและใช้แลกเงินสดหรือรางวัลจริงภายหลัง

Treasure Quiz เป็นเว็บและ deployment แยกจาก RingQuiz แต่ใช้ Supabase project เดียวกัน ตารางและ Edge Functions ใหม่ใช้ prefix `tq_` หรือ `treasure-` เพื่อไม่กระทบข้อมูลเดิม

## 2. สมมติฐานที่ช่วยลดขนาดงาน

- มี Host และ Player คู่เดิมเพียงคู่เดียว
- เปิดเกมพร้อมกันครั้งละหนึ่งเกมเท่านั้น
- ไม่มีบัญชีสาธารณะ ไม่มีรายชื่อเพื่อน และไม่มี matchmaking
- ไม่ต้องรองรับผู้เล่นหลายคนหรือหลายห้องพร้อมกัน
- Host และ Player รู้ PIN ส่วนตัวของตน
- ไม่มีการซื้อสิทธิ์เล่น ทอง หรือเพชรด้วยเงินจริง
- เงินบาทสะสมใช้เป็นรางวัลเท่านั้น นำกลับมาเดิมพันไม่ได้
- การมอบเงินจริงหรือรางวัลจริงทำกันเองนอกระบบ

## 3. ขอบเขต MVP

### รวมใน MVP

- หน้า Host และหน้า Player แยกกัน
- Host PIN และ Player PIN ซึ่งตรวจใน Supabase Edge Function
- เกมตอบคำถาม 8 รอบตามโครงสร้างคงที่
- Preview keywords ก่อนเลือกเดิมพัน
- เดิมพัน Safe, Gold และ Diamond
- Event checkpoint หลังรอบ 2, 4 และ 6
- หีบหลายระดับ ซื้อได้หลายใบ
- ใช้ทองและเพชรให้หมดเมื่อจบเกม
- เงินบาทสะสมและประวัติรายการ
- Reward catalog และคำขอแลกรางวัลแบบง่าย
- กลับเข้าเกมหลัง refresh หรือเน็ตหลุดได้

### ตัดออกจาก MVP

- ระบบห้องหลายห้องและรหัสเชิญหลายชุด
- QR Code และระบบค้นหาห้อง
- สมาชิกหลายคนและ leaderboard
- Finite prize inventory, prize pool versioning และ liability dashboard
- Device pairing, recovery code และ audit system แบบเต็ม
- Redemption หลายขั้น เช่น reserve/approve/refund
- การโอนเงินอัตโนมัติหรือเชื่อมธนาคาร
- การซื้อทอง/เพชรด้วยเงินจริง
- การสร้างคำถามด้วย AI
- คำถาม free-text
- Analytics ขั้นสูง

## 4. การเข้าใช้งาน

### Host

Host เปิด `/host` และกรอก Host PIN ซึ่งเก็บเป็น Supabase Edge Function secret PIN อยู่ใน `sessionStorage` ของ browser และถูกส่งไปตรวจใน Edge Function เมื่อทำคำสั่งสำคัญ

### Player

Player เปิด `/play` ระบบทำ Supabase Anonymous Sign-in แล้วให้กรอก Player PIN Edge Function ตรวจ PIN และผูก auth UID ปัจจุบันกับ `tq_player_profile` ซึ่งมีเพียงหนึ่งแถว

หากเปลี่ยนโทรศัพท์ Player เพียงเข้าสู่ระบบใหม่ด้วย Player PIN เดิม ระบบแทนที่ auth UID เก่า โดยยอดเงินบาทยังอยู่กับ profile เดิม ไม่ต้องมี recovery flow แยก

PIN ไม่ถูกเก็บในตารางหรือ frontend environment ใช้ `HOST_PIN` และ `PLAYER_PIN` เป็น Edge Function secrets

## 5. การเตรียมเกม

Host ทำสิ่งต่อไปนี้ก่อนเล่น:

1. เพิ่มหรือแก้คำถามของรอบ 1–8
2. ใส่ keyword หนึ่งคำต่อหนึ่งคำถาม
3. ตรวจคำตอบและตัวเลือก
4. ตั้งค่าหีบและโอกาสได้รางวัลของแต่ละหีบ
5. ตั้ง Reward catalog เช่น เงินสด 100 บาท หรือบุฟเฟต์สุกี้ 250 บาท
6. กด “สร้างเกมใหม่”
7. Player เปิด `/play` และกดเข้าร่วมเกมปัจจุบัน
8. Host เห็นสถานะ Player พร้อมแล้วจึงกดเริ่ม

เมื่อเริ่มเกม ระบบ snapshot คำถาม ราคา และกติกาหีบที่ใช้ในเกมนั้น เพื่อไม่ให้การแก้ค่าระหว่างเกมเปลี่ยนผลของเกมที่กำลังเล่น

Player เริ่มด้วย 200 ทองและ 0 เพชร

ระบบอนุญาตให้สร้างเกมเมื่อมีคำถามครบ 50 ข้อตามจำนวนของทั้ง 8 รอบ ตัวเลือกไม่ซ้ำ คำตอบอยู่ในตัวเลือก และทุกข้อมี keyword

## 6. โครงสร้าง 8 รอบ

| รอบ | รูปแบบ | จำนวน | เวลา | รางวัลพื้นฐาน | โบนัส | เพชร |
|---|---|---:|---:|---:|---|---|
| 1 | ใช่/ไม่ใช่ | 10 ข้อ | ข้อละ 10 วินาที | 15 ทอง/ข้อถูก | ถูกครบ +50 ทอง | ไม่มี |
| 2 | ใช่/ไม่ใช่ | 10 ข้อ | ข้อละ 10 วินาที | 15 ทอง/ข้อถูก | ถูกครบ +50 ทอง | ถูกอย่างน้อย 9/10 ได้ 1 เพชร |
| 3 | 3 ตัวเลือก | 5 ข้อ | ข้อละ 10 วินาที | 40 ทอง/ข้อถูก | ถูกครบ +50 ทอง | ไม่มี |
| 4 | 3 ตัวเลือก | 5 ข้อ | ข้อละ 10 วินาที | 50 ทอง/ข้อถูก | ถูกครบ +50 ทอง | ถูก 5/5 ได้ 1 เพชร |
| 5 | 3 ตัวเลือกแบบ time bank | 5 ข้อ | รวม 30 วินาที | 50 ทอง/ข้อถูก | ผ่าน 4/5: เวลาที่เหลือ ×5 ทอง | ไม่มี |
| 6 | 3 ตัวเลือกแบบ time bank | 5 ข้อ | รวม 30 วินาที | 60 ทอง/ข้อถูก | ถูก 5/5: เวลาที่เหลือ ×10 ทอง | ถูกครบและเหลืออย่างน้อย 10 วินาที ได้ 1 เพชร |
| 7 | 4 ตัวเลือกแบบ no-mistake | สูงสุด 5 ข้อ | ข้อละ 15 วินาที | 60 ทอง/ข้อถูก | ผ่าน 5/5 เพิ่ม 250 ทอง | ผ่าน 5/5 ได้ 1 เพชร |
| 8 | 4 ตัวเลือกแบบ no-mistake | สูงสุด 5 ข้อ | ข้อละ 15 วินาที | 80 ทอง/ข้อถูก | ผ่าน 5/5 เพิ่ม 400 ทอง | ผ่าน 5/5 ได้ 2 เพชร |

### Time bank

- เวลา 30 วินาทีเริ่มเมื่อเปิดข้อแรกและไม่ reset ระหว่างข้อ
- เมื่อเลือกคำตอบ ระบบไปข้อต่อไปทันที
- หมดเวลาเมื่อใด รอบจบทันที
- ใช้เวลาจาก Server เป็นหลัก

### No-mistake

- ตอบผิดหรือหมดเวลาทำให้รอบจบทันที
- ยังได้รับทองจากข้อที่ตอบถูกก่อนหน้า
- ไม่ได้รับ Perfect bonus และเพชร
- หากมี `mistake_shield` จะกันความผิดครั้งแรกแล้วเล่นต่อได้

ค่ารางวัลเป็น baseline สำหรับการทดลองเล่น สามารถปรับใน config ภายหลังโดยไม่เปลี่ยนโครงสร้างเกม

## 7. Keyword และการเดิมพัน

ก่อนแต่ละรอบ Player เห็น:

- รูปแบบ จำนวนข้อ และเวลา
- ระดับความยาก 1–3 ดาว
- keyword หนึ่งคำต่อหนึ่งข้อ โดยสลับลำดับไม่ให้ตรงกับลำดับคำถาม
- เป้าหมายของการเดิมพัน
- ทองและเพชรปัจจุบัน

ตัวอย่าง:

> รอบ 5 · 3 ตัวเลือก · 5 ข้อ · เวลารวม 30 วินาที
> Keywords: ญี่ปุ่น · แมว · เพลงยุค 90 · วันแรกพบ · อวกาศ

Player เดิมพันหนึ่งครั้งต่อรอบ

### Safe

- ไม่เสียทรัพยากร
- ได้รางวัลพื้นฐานและโบนัสปกติ

### Gold bet

- วาง 100 ทองก่อนเริ่มรอบ
- เป้าหมายรอบ 1–2: ถูกอย่างน้อย 8/10
- เป้าหมายรอบ 3–6: ถูกอย่างน้อย 4/5
- เป้าหมายรอบ 7–8: ถูก 5/5
- ผ่านเป้าหมาย: คืน 100 ทองและได้โบนัสเพิ่ม 50% ของทองพื้นฐาน
- ไม่ผ่าน: เสีย 100 ทอง แต่ยังได้ทองจากคำตอบที่ถูก

### Diamond bet

- วาง 1 เพชรก่อนเริ่มรอบ
- ใช้เป้าหมายเดียวกับ Gold bet
- ผ่านเป้าหมาย: คืนเพชรและได้โบนัสเพิ่ม 100% ของทองพื้นฐาน
- ไม่ผ่าน: เสียเพชร แต่ยังได้ทองจากคำตอบที่ถูก

ลำดับคำนวณคือรางวัลพื้นฐาน → โบนัสรอบ → Event boost → โบนัสเดิมพัน → คืน stake การคูณโบนัสไม่ซ้อนกัน

## 8. Flow หนึ่งรอบ

1. Host เปิด briefing
2. Player ดู keywords และเลือกเดิมพัน
3. Server ตรวจยอดและหัก stake
4. Host กดเริ่ม
5. Player ตอบคำถามตามกติกาของรอบ
6. Server ตรวจคำตอบและเวลา
7. Server คำนวณรางวัลและคืน stake เมื่อผ่านเป้าหมาย
8. Host กดเปิดผล
9. ทั้งสองหน้าจอแสดงผลและยอดใหม่
10. หลังรอบ 2, 4 หรือ 6 ไป Event checkpoint มิฉะนั้นไปรอบถัดไป

คำสั่งวางเดิมพันและส่งคำตอบต้องกันการกดซ้ำด้วย unique constraint หรือ idempotency key

## 9. Event checkpoint

หลังรอบ 2, 4 และ 6 Player เลือกได้หนึ่งอย่าง:

- Skip
- Gold Event ราคา 150 ทอง
- Diamond Event ราคา 1 เพชร

Event สำหรับ MVP:

- `reward_boost_20`: เพิ่มทองของสองรอบถัดไป 20%
- `extra_keyword`: เปิด keyword เสริมในรอบถัดไป
- `bet_shield`: กันการเสีย stake ครั้งถัดไป
- `mistake_shield`: กันคำตอบผิดครั้งแรกของ no-mistake round
- `chest_discount_100`: ลดราคาหีบระดับเงินขึ้นไปหนึ่งใบ 100 ทอง; ใช้กับหีบทองแดง Closeout หรือ Consolation ไม่ได้
- `extra_time_5`: เพิ่ม 5 วินาทีต่อข้อในรอบ per-question หรือเพิ่ม 5 วินาทีให้ time bank
- `tax_50`: เสีย 50 ทองแต่ยอดไม่ติดลบ
- `boss_question`: คำถาม 10 วินาที ตอบถูกได้ 500 ทอง

Server เป็นผู้สุ่ม Event และ Host เปลี่ยนผลไม่ได้

## 10. Prize Shop

หลังรอบ 8 ระบบเปิด Prize Shop Player เลือกหีบกี่ใบก็ได้จนกว่าทองและเพชรหมด

| หีบ | ราคา | ตัวอย่างรางวัลและโอกาสเริ่มต้น |
|---|---:|---|
| ทองแดง | 100 ทอง | 0.01 บาท 60%, 0.10 บาท 30%, 0.50 บาท 10% |
| เงิน | 300 ทอง | 0.50 บาท 55%, 1 บาท 35%, 2 บาท 10% |
| ทอง | 700 ทอง + 1 เพชร | 1 บาท 50%, 2 บาท 30%, 5 บาท 18%, 10 บาท 2% |
| เพชร | 1,500 ทอง + 3 เพชร | 5 บาท 50%, 10 บาท 30%, 20 บาท 17%, 50 บาท 2%, 100 บาท 1% |
| คริสตัลเล็ก | 1 เพชร | 0.10 บาท 60%, 0.50 บาท 30%, 1 บาท 10% |

Host แก้จำนวนเงินและเปอร์เซ็นต์ได้จากหน้า Settings โดยเปอร์เซ็นต์ของแต่ละหีบต้องรวมเป็น 100%

### ใช้ทรัพยากรให้หมด

1. Player เลือกหีบหลักหลายใบใส่ตะกร้า
2. ถ้าเหลือทองตั้งแต่ 100 ขึ้นไป ระบบเสนอหีบทองแดงเพิ่ม
3. เพชรที่เหลือซื้อหีบคริสตัลเล็กใบละ 1 เพชร
4. ทองที่เหลือ 1–99 เปิด Closeout Chest มูลค่า 1 สตางค์
5. ถ้าไม่มีทรัพยากรเหลือพอซื้อหีบตั้งแต่แรก ระบบให้ Consolation Chest มูลค่า 1 สตางค์
6. ระบบยอมยืนยันตะกร้าเมื่อทองและเพชรหลังซื้อเป็นศูนย์เท่านั้น

### เปิดหีบ

- เมื่อ Player เปิดหีบ Edge Function ตรวจว่าหีบนั้นยังไม่เปิด
- Server สุ่มจาก reward table ของหีบ เพิ่มเงินเข้า Wallet และบันทึกผลใน transaction เดียว
- การเปิดหีบใช้ idempotency key เพื่อไม่ให้ refresh หรือ double tap เพิ่มเงินซ้ำ
- ทั้งสองหน้าจอเห็นผลพร้อมกันผ่าน Realtime
- Player เปิดทีละใบหรือกดเปิดทั้งหมดได้

ไม่ใช้ finite inventory เพราะเป็นเกมส่วนตัว Host ควบคุมงบด้วยการตั้งเปอร์เซ็นต์และจำนวนเงินสูงสุดของแต่ละหีบ

## 11. Wallet เงินบาท

เงินเก็บเป็น integer หน่วยสตางค์:

- 1 สตางค์ = `1`
- 1 บาท = `100`
- 100 บาท = `10000`
- 250 บาท = `25000`

`tq_player_profile` เก็บยอดปัจจุบัน และ `tq_wallet_entries` เก็บประวัติแบบ append-only ทุกครั้งที่เปิดหีบ แลกรางวัล หรือ Host ปรับยอด ระบบอัปเดตยอดและเพิ่มประวัติใน transaction เดียวกัน ยอดห้ามติดลบ

เงินบาทสะสม:

- เก็บข้ามเกม
- ใช้แลกรางวัลเท่านั้น
- ใช้เดิมพัน ซื้อ Event หรือซื้อหีบไม่ได้
- ไม่หมดอายุ

## 12. Reward catalog และการแลก

ตัวอย่าง:

| รางวัล | ยอดที่ใช้ |
|---|---:|
| เงินสด 100 บาท | 100 บาทสะสม |
| บุฟเฟต์สุกี้ | 250 บาทสะสม |

Flow แบบง่าย:

1. Player กดขอแลกรางวัล
2. ระบบสร้างคำขอสถานะ `pending` โดยยังไม่หักยอด
3. Host มอบรางวัลจริงนอกระบบ
4. Host กด `มอบแล้ว`
5. Server ตรวจยอดอีกครั้ง หักเงิน เพิ่ม Wallet entry และเปลี่ยนสถานะเป็น `completed` ใน transaction เดียว
6. Host กดยกเลิกได้ก่อน completed โดยเปลี่ยนสถานะเป็น `cancelled` และไม่แก้ยอดเงิน

มีเพียงสามสถานะ: `pending`, `completed`, `cancelled`

## 13. Supabase data model แบบย่อ

ตารางใหม่ใช้ prefix `tq_`:

- `tq_player_profile`: profile เดียว, auth UID ปัจจุบัน, ชื่อ และยอดสตางค์
- `tq_questions`: round, order, type, text, keyword, choices, correct answer, difficulty
- `tq_games`: เกมปัจจุบันและประวัติ, phase, รอบ, ทอง, เพชร และ config snapshot
- `tq_rounds`: เดิมพัน สถานะ เวลา ผลรวม และ Event effect ของแต่ละรอบ
- `tq_answers`: คำตอบรายข้อและเวลาส่ง
- `tq_chest_types`: ราคาและ reward table แบบ JSON
- `tq_chest_opens`: หีบที่ซื้อ/เปิด ผลเงิน และ idempotency key
- `tq_wallet_entries`: ประวัติเงินเข้าออก
- `tq_reward_catalog`: รางวัลที่แลกได้
- `tq_redemptions`: คำขอแลกและสถานะ

ไม่สร้างตาราง room membership, prize inventory, prize pool, pairing หรือ audit เพิ่มใน MVP

## 14. Edge Functions และ Realtime

ใช้ Edge Functions สองตัว:

### `treasure-host-action`

- ตรวจ Host PIN
- จัดการคำถาม หีบ และ Reward catalog
- สร้าง/เริ่ม/พัก/ดำเนินเกม
- เปิดผลและไปขั้นถัดไป
- completed/cancelled redemption
- ปรับ Wallet พร้อมข้อความเหตุผลเมื่อจำเป็น

### `treasure-player-action`

- ตรวจ Player PIN ตอน link profile และตรวจ Supabase JWT ในคำสั่งต่อมา
- เข้าร่วมเกมปัจจุบัน
- วางเดิมพันและส่งคำตอบ
- ซื้อ Event
- ยืนยันตะกร้าและเปิดหีบ
- ขอแลกรางวัล

Realtime subscribe เฉพาะ `tq_games`, `tq_rounds`, `tq_chest_opens` และ `tq_redemptions` ที่เกี่ยวกับ profile เดียว ไม่ต้องสร้าง channel หลายห้อง

## 15. ความปลอดภัยที่ยังต้องคงไว้

แม้เป็นเกมส่วนตัว ต้องรักษาข้อกำหนดต่อไปนี้:

- Client แก้ทอง เพชร เงินบาท ผลคำตอบ หรือผลหีบโดยตรงไม่ได้
- PIN อยู่ใน Edge Function secrets ไม่อยู่ใน source code
- ตรวจ deadline ด้วย server time
- คำตอบหนึ่งข้อต่อเกมส่งได้ครั้งเดียว
- หีบหนึ่งใบเปิดได้ครั้งเดียว
- Wallet update และ Wallet entry ต้องสำเร็จหรือ rollback พร้อมกัน
- RLS จำกัด Player ให้อ่านเฉพาะ profile และเกมของตน
- RingQuiz tables/functions เดิมไม่ถูกแก้

## 17. Recovery

- Refresh แล้วโหลด phase ปัจจุบันจาก `tq_games`
- เน็ตหลุดระหว่างตอบ เวลา Server ยังเดินต่อ
- Retry คำตอบหรือเปิดหีบต้องคืนผลเดิม ไม่สร้างรายการซ้ำ
- หาก Host หลุด เกมคง phase เดิม เมื่อกลับมาจึงกดดำเนินต่อ
- หาก Player ออกจากหน้าหลังซื้อหีบ ระบบพากลับหน้าหีบที่ยังไม่เปิด

## 18. การทดสอบที่จำเป็น

### Unit

- คำนวณรางวัลทั้ง 8 รอบ
- Gold/Diamond bet
- Time bank และ no-mistake
- Event effects
- ราคาตะกร้าและการใช้ทรัพยากรจนศูนย์
- Weighted chest random เลือกได้เฉพาะค่าที่ตั้งไว้
- Wallet และ redemption

### Integration

- ส่งคำตอบซ้ำและเปิดหีบซ้ำไม่เพิ่มรางวัลซ้ำ
- Client แก้ยอดเงินเองไม่ได้
- Wallet balance ตรงกับผลรวม entries
- Host/Player เห็น phase เดียวกันผ่าน Realtime

### End-to-end

- ใช้โทรศัพท์สองเครื่องเล่นครบ 8 รอบ
- ผ่าน Event checkpoints ทั้งสามครั้ง
- ซื้อหีบหลายใบจนทอง/เพชรหมด
- เงินเข้ากระเป๋าและยังอยู่หลังเริ่มเกมใหม่
- ขอแลกรางวัลและ Host กดมอบแล้วได้

## 19. Deployment

- Frontend เป็น Vite/React/TypeScript project ใหม่ มี URL และ build แยกจาก RingQuiz
- ใช้ Supabase URL และ anon key ของ RingQuiz project
- Migration และ Edge Functions ใหม่ใช้ namespace Treasure Quiz
- เปิด URL เฉพาะให้ Host และ Player ใช้ โดยหน้า Host/Player ต้องผ่าน PIN
- เริ่มจาก deployment สำหรับทดสอบก่อน แล้วใช้ URL เดิมต่อเมื่อทดลองเล่นผ่าน

## 20. Definition of done

MVP เสร็จเมื่อ Host และ Player ใช้โทรศัพท์คนละเครื่องเล่นครบ 8 รอบได้, keywords และการเดิมพันทำงาน, Event ทั้งสาม checkpoint ทำงาน, Player เลือกและเปิดหีบหลายใบจนทอง/เพชรหมด, เงินบาทสะสมข้ามเกม, แลกรางวัลจริงผ่าน flow แบบง่ายได้ และไม่กระทบ RingQuiz เดิม
